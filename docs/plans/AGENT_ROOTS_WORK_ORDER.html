The drain rate is one item per session

A review run on 2026‑08‑19 resolved exactly one of the 353. That is the measured rate at which agent-driven, one-at-a-time review actually empties a queue — so the work queue is 353 sessions of work. It is not evidence that agents are bad at reviewing; it is evidence that “we write it to a queue for the user to review” was never a finished workflow. Any design that only handles items one at a time inherits that rate (P5.2).

SettledSeven decisions the implementer inherits

D1 · The auto‑apply rule, stated once

Already articulated in exactly one place — memory_actionable_count's docstring: “a judgement the user may decline … a finding that can never be cleared would hold the audit at needs_attention until people stop reading it.” Promote it to policy:

A migration may auto‑apply only if it can name exactly one correct outcome for every affected item, and the change is confined to metadata Ciaobot generates. Anything that moves or rewrites the user's own prose, or has even one ambiguous case, is surfaced and never applied.

D1 applied — explains all three existing behaviours without special pleading
MigrationOne outcome per item?Verdict
vault_migration.py — type: aliasesYes — TYPE_ALIASES maps to one target; unmapped is reported, not guessedauto-apply correct today
vault_migrate_links.pyNo — rewrites link syntax through the user's prosesurface correct today
vault_rehome.pyNo, by construction — needs_judgement is non‑emptysurface missing today

D2 · Separate pending actions from defects

run_os_audit's actionable_count sums notices_found with orphans, duplicates, frontmatter errors, broken links and failed runs — so a healthy vault with one optional migration reports needs_attention. Split into defect_count and pending_action_count; status keys off defects only.

D3 · One shared proposal‑kind registry

Replace all three regexes with one module owning the kinds and their accept semantics. Each kind declares its own accept action: [memory]/[profile] edit a bounded region; [rehome] is a file move with a destination and a reason and must never inherit an “add to memory” button. An unregistered kind is a registration error, not a silent zero.

D4 · Survey‑then‑apply receipts, generalised

Survey at boot with apply=False, write status: "surveyed" plus counts, detector reads only the receipt. read_receipt must gate on status == "migrated", not on receipt existence — vault_migration.migrate_if_needed has that bug today, so a survey receipt would permanently block the real migration.

D5 · Logs/ stays global; Templates/ becomes a mirror source

Census found Logs/ holding 1423 of 1985 vault notes (72%) as a sibling of the workspaces. Promote to <install>/Logs/ unmoved: derived output, not curated content; not moving it removes 72% of the migration's file‑count risk; and 1350 chat ids cannot all resolve to a workspace. Templates/ (5 files) becomes <install>/templates-src/.

D6 · Missed once schedules become a tile

catch_up() is right for recurring reconcilers — late is harmless and the next run subsumes it. Wrong for once: those catch up across days, so a missed 3pm Monday reminder fires whenever the server next starts, un‑backdated, with nothing telling the agent it is stale.

D7 · Accept still leaks until phase 9 — gate the button

There is one CLAUDE.md. So an accept button on a work proposal writes a region injected into every personal session. Until phase 9, accepts for [memory]/[profile] must warn explicitly that the fact becomes visible in every workspace, or be disabled outside the primary.

ExecutionTen phases

Phases 0–9 ship independently. Phase 10 is one indivisible release — the deletions make a partial re‑root fail‑open, so it cannot be decomposed.

P1 Proposal‑kind registry & the undercount fix ships alone

Everything downstream counts proposals. Fix the counting before building a UI on top of it.

P2 The audit split (D2) ships alone

Without this, the weekly hygiene routine can never report a healthy workspace while any migration is outstanding — and the cut makes that permanent for every install.

P3 unrehomed_people notice (D1, D4) safe alongside OKF

The bug vault_rehome repairs shipped in every version until 2026‑08‑19. Every multi‑workspace install has some version of it and no way to learn that.

P4 The surfaced‑actions strip gates phase 10

Also fixes “weekly is too slow” as a side effect: the strip polls on app open and window focus, so an upgrade action appears the day of the upgrade rather than the following Sunday.

P5 Queue review UI — making an action actionable the 417 items

A surfaced action that cannot be acted on is a notification, not a workflow. The queue depth is the measure of the gap.

P6 Vocabulary and the resolver no behaviour change

ARCHITECTURE.md uses “workspace” for both the install directory and the logical workspace, in adjacent paragraphs. 375 workspace_root references across ~40 modules mostly mean the install root — renaming what an existing name means is how this ends up half‑rooted.

P7 Thread it through the seam no behaviour change

The seam is one line, and the call site already knows the workspace — it just discards it.

P8 Session paths — the silent‑breakage guard do not skip

_claude_projects_dir slugs the cwd into ~/.claude/projects/-Users-me-repos-ciao. Change cwd and that path moves: _validated_resume_session gets None, logs “stale locally”, and starts fresh. Silent amnesia, not an error.

P9 Per‑root memory tools & the MCP allowlist closes the worst leak

The sixth leak is the sharpest: every MCP server is reachable from every workspace, scoped only by a denylist — fail‑open. What leaks is credentialed authority, not text. And it is the only leak fixable before the cut.

P10 The cut — one indivisible release not decomposable

Deleting _entity_visible_in_workspace while an un‑rooted install exists leaves no filter over a still‑prefixed index — every entity visible in every session. Fail‑open, strictly worse than today. So the deletions and the re‑rooting are one release, atomic per install.

Gate: do not start P10 until every box in P1–P9 and V1–V3 is checked. A migration that can stop halfway is worse than one that refuses outright.
