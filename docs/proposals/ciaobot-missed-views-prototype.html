P1

New automation

NewScheduleForm.vue
  • Same sections as the detail page. When, Where it runs, Model and Results, in the order SchedulePanel already shows them, so creating and reading an automation look alike.
  • Prompt first. It is the part people think about; the schedule is the detail.
  • Labels move into hairline key/value rows. No uppercase field labels, no bordered card around the form.
  • Controls match the rest of the app. Frequency and archive behaviour become segmented controls, weekdays become sentence-case toggles, the model uses the composer's model chip.
  • Normal-size primary action. One pink "Create automation" at the end, next to Cancel, instead of a full-width bar.
  • Rail shows the result. The next two runs, computed from the choices, replace the unexplained "i" button.
P1

Memory → Map

MemoryMapView.vue
  • Page grid with a rail. The graph and list sit in the main column; the rail carries the same Vault numbers as Review, so switching tabs does not move them.
  • The sidebar goes back to navigation. Search and Categories stay; Most connected, Needs review and Recently written move into the rail. The long explanatory paragraph goes.
  • One orphan filter. "Hide orphans" and "Only orphans" become one menu: All notes, Linked only, Orphans only.
  • Named canvas controls. Zoom in, Zoom out and Fit sit in a small bordered group with accessible names, as DESIGN.md's canvas rule requires.
  • Plain table. Sentence-case headers, tags as muted text, link counts as numbers without the pink bar, "Needs review" as the squared 4px tag.
  • Path start/end move to a row menu. Two bordered buttons on every row become one "⋯" with Set as path start and Set as path end.
P1

Settings → Workspaces

SettingsView.vue
  • Collapsed rows. Each workspace is one hairline row with an accent dot and a summary line; Edit opens it in place. Only one is open at a time.
  • Save only when something changed. One primary "Save changes" appears inside the open row, with Discard. No Save on untouched rows.
  • Archive moves into the row menu. It is rare and hard to undo, so it no longer sits as an orange button on every row.
  • Smaller swatches. 26px accent swatches with a ring on the selected one, instead of 40px circles.
  • Real page names. Sentence-case workspace names; "+ Add workspace" becomes "New workspace", matching the sidebar entry.
  • Rail stays useful. On this page gains Archived, plus the 1–9 shortcut hint.
P1

Settings → Models & providers

SettingsView.vue
  • No pink Reconnect bar. Reconnect is only needed when a login breaks, so Reconnect and Log out move into the provider's "⋯" menu. Verify stays as a text link. When a provider is disconnected, Reconnect becomes that row's single primary.
  • Defaults as indented rows. Model, permissions and thinking are hairline rows under the provider instead of a bordered box of three selects.
  • Chips that match the composer. The default model uses the composer's model chip; thinking uses the same Auto/Low/High segmented control as the picker below.
  • One critique control. The free-text field, its Reset and the separate multi-select collapse into one chip that opens a multi-select.
  • Rail shows provider status. A glance tells you whether each CLI is working without scrolling.
P2

Settings → Automations

settings/SettingsAutomation.vue
  • Real switches. A pink "On" button is read as an action. A switch with a visible On/Off word is a state, and keeps the pink for the accent.
  • Sans titles, shorter descriptions. Monospace is for technical metadata, not row titles.
  • Refresh is a text link at the section's right edge, like every other section action.
  • Empty state is a muted line under a "Recent runs" heading, not a violet-edged box.
  • Rail with run status, linking to the Automations page where scheduled runs already live.
P2

Settings → Skills, Subagents, Commands, MCP servers

SettingsView.vue · SettingsMcpServers.vue
  • One list pattern for four tabs. Heading, one neutral "New …" button, "Ask Ciao to write one" as a quiet link, then hairline rows with a squared Custom/Built in tag and Edit.
  • Rail with counts and sync state. These tabs had an empty right side; the rail says how many exist and whether each runtime has picked them up.
  • Empty states that explain. One sentence on what the thing is for and an "Add one" link, instead of "No subagents found."
  • Drop the "+" prefixes in button labels, matching New chat and New workspace.

Skills rendered a blank pane against the e2e fixture (its /api/skills stub returns {}). Worth checking whether the real tab also goes blank when the response is empty or malformed, rather than showing an empty state.

P2

Memory → Suggested, Notes to revisit, History

ProposalReviewPanel · VaultReviewPanel · ProposalHistoryList
  • Neutral per-row actions. A pink Review on every suggestion competes with itself. Review becomes a neutral button, Dismiss a quiet link.
  • Bulk tools out of the way. "Select all" becomes a Select link that turns on checkboxes; "Dismiss older than N days" moves into the section's "⋯" menu.
  • Notes to revisit loses its inset. Content starts on the column edge like every other tab; the count becomes the tab badge; "refresh" becomes a Refresh link.
  • History filters become segmented controls in sentence case, instead of lowercase pills with a pink outline.
  • Sidebar filters in sentence case. "Kinds · all · memory" becomes "All kinds" and "Memory", like the Map sidebar's Categories.
P2

Subagent transcript

SubagentChatView.vue
  • Chat header shape. Back icon button, the agent's name as the title, the parent chat as a muted crumb. The separate strip showing the raw id goes.
  • "Read only" as a squared tag in sentence case, not an uppercase pill.
  • Chat empty state. Heading, one muted line and a link, the same shape as "Start with a request". No italics.
  • Composer replaced by a note bar. A disabled full-width input looks broken; a short line with Go to chat says what to do.
  • Rail with run facts in the Work details vocabulary.
P2

Model picker popover

ModelSelector.vue
  • Group labels in sentence case at 12px, provider name only. No uppercase monospace.
  • Selection by check and tint. The selected model gets a check and the hover surface, not a solid pink fill that reads as a button.
  • Default is labelled. "Workspace default" on the right says what Automatic means.
  • Thinking uses the shared segmented control in sentence case, as in Settings → Models.
P3

Settings → Notifications

settings/SettingsNotifications.vue
  • Status as a key/value row with a warning dot and the fix on the line below, instead of a callout box that fills the page.
  • Show what can be controlled. Rows for the kinds of notification make the tab useful when permission is granted. Only add these if the backend already distinguishes them; otherwise ship just the status row.
P3

This device

DevicePanel.vue · /device
  • Plain sections instead of cards. Sentence-case "Role" and "Local app" headings with hairline rows.
  • State as text with a dot, not orange badges repeated twice.
  • Clearer destructive wording. "Force become host" becomes "Make this the host…", red outline, with a confirm step.
  • Same page grid, even though the page lives outside the app shell. It stays on the loopback device origin (see docs/REMOTE_BOUNDARY.md); only styling changes.
P3

Connection banner, sidebar footers, New chat picker

ChatLayout · ProjectSidebar · NewChatPicker
  • Banner in the product voice. Sans 13px on a light warning tint, plain sentence, one link and one neutral button. The monospace strip reads like a debug console.
  • Footer buttons move into section labels. "+ New Project" and the pink-outlined "+ New Automation" at the sidebar bottom become a "New" link on the Projects and Routines labels. The archive icon joins the Projects label's menu.
  • Picker selection matches the sidebar. Accent-tinted fill with a 2px inside edge, not a pink border box; ↵ shows on the selected row.
