# Pass 9: skill proposals

Report the skill proposals you find in the queue, and nothing else. Settle nothing: `ciao skill-proposal-remove` records a decision (implemented, or decided against), and an unattended run can make neither. You did not edit the skill, and a judgement that a proposal is not worth building is a judgement about somebody's work that a person has to make.

1. Read at most five proposal files per run, oldest first: never the whole queue, and not the routed drafts: do not run `ciao skill-drafts`.
2. Put what you found for each planned proposal into the run's technical report. Do not list proposals one per line under **What needs you**: give one aggregate line for them.
3. Report only files you actually read.
4. You may add evidence: a new sighting of the same finding accumulates on the record, which stays queued. A settled record stays settled and is not reopened.

Proposals that belong in a bounded region stay queued too; that is the existing queue's job, not a settlement. Proposals you did not read are the next run's work, so do not list them.
