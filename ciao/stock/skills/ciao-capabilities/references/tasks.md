# The task board and after-this-update tasks

## The task board (Tasks page)

- **One board per workspace**, four columns — To do, In progress, In review, Done — over plain Markdown files in your vault under `Workspace/Tasks/`, one per task. Drag a card to another column to move it (or Shift+←/→ on a focused card); on a phone the board is one list and status is set from the task. Nothing proprietary: a task is a file you own, and hand-editing one is read back on the next refresh.
- A task carries a title, a Markdown description (links, acceptance criteria, result notes), an optional project, an optional due date, and who it is for. Filters by project, due date and status; a due date is a calendar day, never an automation — nothing runs on it and nothing reminds you.
- **Manual work needs no chat at all.** File a task, do it, tick its checkbox. "For the agent" is an assignment label, not a trigger.
- **Delegate to agent** (in the task's editor, under *Agent*) hands one task to the agent as **one ordinary chat** in the task's project (or that workspace's General), titled for the task, with the description quoted into it. The preview sheet has an optional **Instructions for the agent** field — how to go about it, what to avoid, what you expect when it is done — added after the description for that attempt only, without editing the task. The chat is an ordinary attended chat: a permission or approval card the agent raises shows up there as a normal Needs-you card, exactly as in any chat, and it waits for you. Use it for "here is the work, go and do it".
- **The agent reports how far it got.** Before its turn ends, a delegated agent reports *done*, *blocked* or *needs input* with a short summary, shown on the card. A turn that ends without a report reads **Unfinished**, never as a result.
- **The agent's turn finishing is not the task finishing.** A turn the agent reported done moves the card to **In review** and stops there. **You** approve it: the card's **Approve Done** asks for a completion note (or an explicit complete-without-note) and closes the task in one write. The delegation stays in the card's history with its chat still one click away. When you reject a result, approve it or delete a task you may give an optional reason; skipping it costs no extra click, and the decision is logged with or without one. That log is kept apart from the task, so the reason you deleted a task for is still there after the task is gone. The agent cannot approve a delegated task: one linked to a chat or a delegated run is refused, by design. It can close a plain task when you tell it the task is done. While a task is in progress or in review, you or the working agent can add progress notes on the task itself; those notes are what a later resume and the completion memory pass read, and they are not a copy of the chat.
- **Closing a project asks how it ended.** Complete on a project asks completed or stopped, plus an optional note. The note is saved on the project document, chats are archived, and open tasks stay on the board.
- **A card can disagree with itself, and the board says so.** If a task's own fields contradict each other — an attempt that ended while the card still reads "in progress", a review badge with nothing to review, a chat the app cannot see — the card names the inconsistency and the controls that resolve it instead of quietly fixing it.
- **Every attempt is listed in the task's editor** (the *Agent* section): which chat it ran in — open or archived, each one opens — how it ended, and what the agent said. The same record is written into the task's own Markdown file as a *Delegation log*, so it survives in the vault and reads in any editor.
- **Approved work teaches Ciaobot how it is done.** Approving a delegated task archives its chat and runs a memory pass that treats it as a worked example: it proposes a skill update, a new skill, or memory notes for the procedure it followed, all waiting in **To decide** for you to accept.
- **Archiving the chat does not lose the work.** Unfinished work in an archived chat is paused, and the card offers **Continue in a new chat**: the new chat is handed the earlier attempts' summaries and transcripts, so it picks up where the last one stopped.
- **Every task has its own address**, `/tasks/<id>`, which opens it on the board. The agent links tasks that way in chats and notes (a daily log's carryover, for one), so clicking one opens the task in place; the address bar shows it while a task is open, so you can copy it.
- **Link a chat to a task.** Ask the agent to link this chat to the task (or use × on the task to unlink). The task lists every chat that worked on it, and those chats can add progress notes.
- From a chat, an agent can read and edit the board with `ciao task list | get | create | update | move | delete | delegate`, can `stop`/`resume`/`retry`/`detach` a delegation, and reports its own outcome with `ciao task report ID --outcome done|blocked|needs_input --summary-file FILE.md`. If you clearly ask it in an attended chat, it can run `ciao task delete ID --revision REV --reason-file FILE`, with the reason you gave: that permanently removes only the task record, including notes and history stored in its file, and leaves its chats, running turns and attempt history alone. A scheduled or otherwise unattended turn is refused (`unattended_forbidden`), so the request has to come from you. Deletion is neither completion nor `ciao chat delete`. It can close a task as done with `ciao task complete ID --revision REV --reason-file FILE` only when you tell it the task is done, giving your reason (stored as the completion note); a task linked to a chat or a delegated run is never closed that way, and `move --to done` stays refused. Approving delegated work is yours, always.
- Not in the board: ordering cards within a column, priorities, recurring tasks, due-date reminders, or anything running on your behalf without you.

## After this update (the update task surface)
- **Home shows an "After this update" group** when a Ciaobot version leaves work behind for the workspace you are standing in: follow-up cleanups an upgrade makes necessary. Each card is one task with a one-line reason and the version that introduced it, and the buttons are the ones its state allows — **Start in chat** for a new one, **Resume chat** for one already under way, **Review proposals** for one whose chat is waiting on your decisions, **Try again** for one whose last attempt failed, and a quiet **Check again** (never a start button) where Ciaobot cannot yet tell whether a *new* task applies. Once a chat exists, **Resume** and **Try again** stay available whatever Ciaobot's check says, because the work is already under way and Ciaobot's own detector is the usual reason it looks "not needed" again — the detector sees the condition is gone before the completion check has confirmed the work is finished. A task Ciaobot has decided does not apply here, and that nobody has started, gets no card at all. Home lists the open tasks; a zero-task Home shows nothing at all rather than an empty box.
- **Hiding a task is not finishing it.** "Hide it" records "not this one" for that task revision in that workspace, and the confirmation says plainly that a chat which is already open is neither cancelled nor marked done. The task is reopenable — **Settings → Overview → Update task history** lists everything that was hidden, finished, failed, or could not be checked, grouped by scope, with **Reopen** (which re-checks whether the work still applies rather than replaying the old instructions) and **Open its chat**. That history shows *when the answer was last checked* and *when you decided* as two separate times, because a decision is not a re-check.
- A task is never marked done just because a chat was opened: a completion check has to confirm the work is finished, and if it cannot, the card says so instead of claiming success. The first real task is **Review this workspace's Learnings.md entries**: a lesson only retires when every finding filed against it has been verified into a skill or rejected by a person, and the entries no proposal has ever linked are exactly the ones nothing is watching. The review reads each of those itself, keeps the lessons that still hold, and retires the ones whose subject is gone, that are superseded, duplicated or already in a skill, naming the evidence for each (every removal is reversible from its receipt). Its card appears when there are entries the reconciliation will not retire, and it is finished by a **durable review receipt for the document as it stands** — generating the table, or waiting on an approval, is not completion. An empty approvals list is a decision, so a run that reads the whole table and removes nothing still records one and still finishes the task. The same workflow is `ciao learnings-cleanup` for the terminal; see `docs/DEVELOPMENT.md` for the table, the approval file and `--revert`.

## Task rules
- **Ciaobot learns from your task decisions.** Each week it distills what you deleted, rejected or approved (and why) into `Workspace/Task-Rules.md` in your vault. You can edit that note freely outside its fenced section; delegation and task creation read it as evidence of your preferences, never as an order.
