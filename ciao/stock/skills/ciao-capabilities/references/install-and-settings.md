# App, settings and installation

## App and system surface

- **Settings page**: Home (restart and app actions, keyboard shortcuts, PWA password (always on), **network access** (every interface or this computer only), **developer** switches (developer mode, source checkout, log level), workspace health, main workspace path (with **Move…**, on the computer running Ciaobot, to move the whole install folder elsewhere on the same disk: it stops, moves, repairs paths, repoints the service and restarts, and open chats carry on; the CLI twin is `ciao workspace-move <new folder> --apply`; on a Linux server the administrator runs that with `sudo` instead, because the service account cannot stop its own unit) (a warning appears under the path, in the setup wizard, the Move dialog and `ciao setup` when the folder is inside iCloud Drive, Dropbox, Google Drive or OneDrive, or in Desktop/Documents synced by iCloud), package update, **update task history**, notifications in the browser, appearance), Workspaces (including Google Workspace), Providers (chat provider connections and per-provider defaults, including each provider's Session insights model), Skills, Subagents, Commands, MCP (read-only provider-native configuration and live chat status, with provider CLI setup/auth instructions), Automations, and Notifications. A workspace can live in Desktop, Documents or Downloads on a Mac where the installer added Ciaobot Server: macOS asks once for access (allow "Ciaobot Server"). Moving a workspace into or out of those folders with Move… is supported on a Mac with the Ciaobot Server host (the move runs as the host, so the same grant covers it); on a Mac without that host the move is refused.
- **Workspace extensions in the UI**: the Skills, Subagents, and Commands tabs in Settings manage Ciaobot assets. The MCP tab reads provider-native Claude Code and OpenCode configuration and live status from already running chats in the selected workspace; it never writes configuration, secrets, or starts a server. Configure Claude servers from the workspace directory with `claude mcp add --scope local ...`; authenticate with `claude mcp login <name>` from a terminal. Configure OpenCode V2 servers with `opencode mcp add ...`; authenticate with `opencode mcp auth <name>`. After a server, plugin or skill changes, a chat picks it up when the agent runs `ciao chat reload` (same conversation, continues on its own); new chats load it automatically. Use the [Claude Code MCP guide](https://code.claude.com/docs/en/mcp) and [OpenCode V2 MCP guide](https://opencode.ai/v2/docs/mcp-servers/). Every server declared in a workspace's `.mcp.json` loads in its Claude chats; `mcp__<name>` in the workspace's tool deny-list blocks one. The per-workspace "claude.ai connectors" toggle in Settings → Workspaces keeps the Claude account's claude.ai connectors (Slack, Jira, …) out of that workspace's Claude chats.
- **Installing and updating**: the engine installs with one line — `curl -fsSL https://github.com/raffaelefarinaro/ciaobot/releases/latest/download/install.sh | sh` — and you open `http://localhost:8443` in a browser. To update, run that one line again, or use **Settings → Home**, where one **Update & restart** click downloads, verifies and applies the engine update. There is no separate app to update: v1.0.0 retired the old macOS `Ciaobot.app`, and a machine that still has it runs the installer with `--migrate` (`... install.sh | sh -s -- --migrate`), which installs the engine *and* removes the old app bundle, and only if that removal could not run does `ciao desktop uninstall` still have to be run by hand (details in the repo README). The engine runs on macOS 13+ (Apple Silicon), on Linux, and on Windows 11 (x64 or ARM64, preview); the PWA itself is installable from any browser. When the browser offers no install prompt, the Home setup card links to the install steps for the platform and marks the step done once the app is installed.
- **Other devices**: open Ciaobot from a phone or another computer. Settings → Home → Other devices lists every address this engine answers on, each with a QR code, and every device signs in with the Ciaobot password. Only an HTTPS address can install the app and get notifications: run `tailscale serve --bg 8443` and Ciaobot finds the Tailscale address on its own, or paste the address of another HTTPS proxy. Plain LAN addresses work in a browser only.
- **Forgotten password**: the installer generates a random one. On the host, the login page's **Sign in on this computer** opens a signed-in tab, and Settings → PWA password then sets a new one without the old password (only in a browser on the host; other devices still need the current one). Otherwise the password is `PWA_AUTH_TOKEN` in the workspace `.env` (default `~/Ciaobot/.env`), or `ciao setup-url --workspace <folder>` prints a one-time localhost login link. Nobody can reset it from another device.
- **Linux/VPS hosting**: the engine and PWA run on Ubuntu 24.04 (Python 3.12, Node 22) as a systemd service under a dedicated account, with application code administrator-owned and the workspace private to the service account. Use any browser or installed PWA as the client; agents execute on the server with its files and credentials. Setup details: `docs/LINUX.md` in the Ciaobot GitHub repo.
- **Windows 11 (preview)**: install from PowerShell with `irm https://github.com/raffaelefarinaro/ciaobot/releases/latest/download/install.ps1 | iex` — no administrator rights; it installs the engine for your account, puts `ciao` on your `PATH`, and registers a per-user logon task so the engine starts when you sign in. Claude Code installs with its native Windows installer and OpenCode 2.x with `npm install -g @opencode/cli`. Apple Intelligence is Mac-only. Engine updates on Windows use the same Settings -> Home card and `ciao update stage` / `ciao update apply` as on macOS; a failed update rolls back to the previous engine by itself. Details: `docs/WINDOWS.md` in the Ciaobot GitHub repo.
- **Local HTTP API**: the app serves an API for the PWA and the operator, behind the PWA session cookie; it is not a surface an in-chat agent drives. Agents use `ciao` commands, which apply workspace confinement, the plan-mode gate and telemetry. `ciao help` lists them with their flags. The API recipes for operators are in `PWA_API.md` in the Ciaobot GitHub repo (`raffaelefarinaro/ciaobot`).
