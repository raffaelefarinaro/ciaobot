# Memory and the vault

## Memory and the vault (second brain)

- **How memory works, in plain terms.** When a chat is archived, Ciaobot re-reads it and writes down only what will matter later — a preference, a lesson, a person, a decision — straight into the place it belongs: things true everywhere go into a small always-loaded memory (the `ciao:memory` / `ciao:profile` regions in `AGENTS.md`), project facts into that project's doc, people into `People/<Name>.md`, reusable how-to lessons into `Workspace/Learnings.md`. Every remembered fact is dated, and when a fact changes the new version replaces the old one. Git backs the vault up, so a wrong write is undone by reverting it; there is no approval queue. A nightly "Workspace care" routine tidies all of this: it merges duplicates, retires expired facts, re-checks old notes once a week, and rotates logs.
- **Doubtful items and proposals.** What the agent is unsure of goes on one plain Markdown list, `Workspace/Unsure.md`: tick a line to approve it, delete a line to reject it. A weak pattern seen in fewer than three chats is a line on that list too, and becomes a fact once it has shown up in three. A skill edit, a guide edit, an upstream GitHub issue or a note retirement is a proposal file under `Workspace/Proposals/` (front matter with type, target, title, summary, rationale, evidence, proposed change, created and status; `ciao proposal-check` validates it); you file the issue or apply the edit from that file, or ask the agent to. Rows left in the older review queue (`Workspace/Memory-Proposals.md`) are drained into these by the nightly care run.
- **What is automatic vs. what is yours.** Automatic: extracting facts from archived chats, writing confident state-shaped facts into place, deduplicating, dating, nightly tidying, and search-index upkeep. Yours: everything on the Unsure list, every proposal file, and the choice to retire or delete a note — nothing is deleted automatically, and aging or unused facts are only reported. Reusable lessons are recorded directly with `ciao memory learn`. You can also just tell any chat "remember this" or "forget that". Region caps are advisory — a full region never blocks a durable fact; consolidation (or raising the limit) is what makes room.
- The vault is standard, open markdown: notes, project folders, `AGENTS.md` (which also holds the bounded memory regions), a vault `MEMORY.md` (curator notes — separate from the bounded regions), a generated `INDEX.md` and `VOCABULARY.md` from frontmatter and markdown links. It is agent-agnostic and remains useful without Ciaobot.
- Vault tooling: search (`ciao vault search`, which covers vault notes, not archived transcripts) before adding duplicate facts, and refresh the index (`ciao vault-index`) after larger edits. Read-only recall searches with `ciao vault search`, uses the truncated snippets to pick the best-matching note, and reads that note before answering, because a snippet can look settled while a later change, negation or condition sits further down; it reads another match only when identity or a conflict stays open, and abstains rather than guessing when the answer is still missing. Snippets and notes read are private evidence: only what the question needs goes into the answer, and a recall leaves the vault unedited. This is inline system-prompt policy, not a separate skill. The typed Ciaobot operations (projects, chats, subagents, automations) are the `ciao <noun> <verb>` commands, listed in the bundled `ciao-cli` skill; use `ciao help <topic>` for the command family, for example `ciao help vault`, `ciao help project` or `ciao help chat`, rather than guessing a name. The bounded memory regions can be edited directly with `Edit` on `AGENTS.md`, or, for text you wrote yourself, `ciao memory update` (check usage with `ciao memory status`). A fact from the user or a conversation goes through `/remember`, which writes it where it belongs (or puts it on the Unsure list when the agent is unsure). Vault-maintenance edits are the `ciao` CLI (`ciao vault-index`, `ciao vault-lint`). Files a script or schedule writes into the vault can be listed, one glob per line, in a `.ciaoignore` at the vault root (for example `automations/*/PROMPT.md` or `Workspace/email-triage/proposals/`), so `ciao vault-lint`, `ciao os-audit` and the Memory Map stop treating them as notes.
- **Memory Map** (`/memory`): an interactive graph and list view of the whole vault for one workspace — nodes are notes (colored/typed from frontmatter), edges come from `related:`/`relatedTo:` frontmatter and relative markdown links in note bodies. Search, filter by category, sort the list by links or by when each note was last updated; clicking a note opens it in a docked tile and lights up its neighbours, and notes that have gone unchecked too long carry an amber ring. A note is not the unit anybody keeps current, so a node also reports the **facts inside it**: each list item carries its own `[verified: YYYY-MM-DD]` stamp, and the tile names the overdue facts and says plainly when part of a note is **not a fact anything here can check** — a paragraph, a table, a quote. The weekly Workspace care run re-checks stale notes against their sources and edits them directly, putting doubtful ones on the Unsure list.

- **Import conversations** (`/memory/import`, in Memory's sidebar and named in the first-run welcome — the same page either way): bring facts you already told another agent into this workspace, rather than re-typing them into a fresh vault. It reads **Claude Code** and **OpenCode** sessions the engine host already has for that workspace, and it is **opt-in and never automatic**: nothing is scanned until you press Find, and nothing is read until you tick a conversation.
  - **The consent screen is the feature.** You pick the conversations yourself (nothing is pre-selected), and before anything runs the confirmation names each one with its turn count, its own first date and what the reader omitted, then the provider and model that would receive the text, an input-volume estimate and the per-batch cap. Ciaobot's own conversations are never offered, an unreadable one says why, and a source whose version this importer cannot read says *Unsupported version, export a file instead* rather than offering a button that does nothing.
  - **Every fact waits for you.** The extraction is a single tool-less turn that can only add lines to the Unsure list — it has no tools at all, so it cannot edit a note, run a command or call `ciao` even if the conversation contains an injection. Nothing reaches your memory until you tick a line and the agent writes it, each line carrying the date of the *message it came from*, so a two-year-old conversation files facts that stay two years old rather than looking verified today.
  - **One batch at a time, and you can stop it.** The runs list shows progress per conversation; cancelling stops the ones not yet started, keeps every line already filed, and says plainly that text already sent to the provider cannot be unsent. A conversation that changes is a new attempt beside the old lines, never a silent overwrite.
  - **Old snapshots expire; memories do not.** Ciaobot keeps a private copy of what an import read and drops it about a month after the import settles. A fact you approved keeps a short record of the conversation and message it came from, so an imported fact stays attributable after that copy is gone.
  - What it does not do: no continuous monitoring or background re-scan (run it when you want), no reading a Claude account export, no cache or cookie scraping, and nothing from a phone — the scan runs on the machine Ciaobot runs on, and a browser can only choose among what that machine already has.

- **Memory backup** (Settings → Advanced → Memory backup). One private git repository at the data folder backs up every workspace together: their memory, skills, subagents, commands and archived workspaces, and never credentials, caches or the transcript archive. **Set up in Ciaobot** starts a setup chat that connects a private GitHub repository for it, which needs the GitHub CLI signed in. **Copy setup prompt** copies the same instructions for any agent to run on that machine. Once the repository is connected, the engine commits and pushes the durable scope every five minutes on its own, with no restart.

## Task rules
- **Ciaobot learns what you keep and drop.** Each week it distills your task decisions into `Workspace/Task-Rules.md`. Edit it freely outside the fenced section; agents read it as evidence, never as an order.

## Shared brains
- **A shared brain is a team's notes folder you link for reference.** In **Settings → Overview → Shared brains**, choose **Folder** or **Git repository**, enter an absolute path (and optionally a name; it cannot be renamed later, so remove and re-add to rename it), and link it. Up to five per workspace. A folder link reads files in place on this computer: Ciaobot never pulls, fetches, syncs or updates existing files, and local availability does not confirm that Google Drive, iCloud or another sync service finished syncing. A Git link needs a dedicated repository cloned on the computer running Ciaobot, outside the Ciaobot install and every vault, with a valid SSH or HTTPS origin and a tracked branch; Ciaobot updates that checkout with fast-forward-only pulls (about every 30 minutes). Your vault is not automatically synced to either kind; only a specific note is published to a linked brain after a human reviews and approves it. A Git link can publish a new or changed note. A folder link can save a newly reviewed note but never replaces or deletes an existing file there, because an ordinary folder has no safe conditional replacement. A Git brain's Settings row can instead record an explicit automatic-sharing choice naming that repository and its audience; automatic sharing is not active yet, every link starts at review, a healthy choice survives a normal restart, and removing and relinking a brain or restoring an archived workspace returns it to review. The exact grants are fenced and journaled before origin reads, so a failed invalidation leaves the old grant paused and revocable. Ciaobot never claims that Google Drive, iCloud or another sync service has finished syncing. The agent has no managed command to create, seed, clone or link a repository; linking is done in Settings. For Git, public HTTPS can be used to read updates; publishing needs noninteractive write access, use SSH when the remote requires authentication, and private HTTPS credential helpers are not used.
- **How the agent uses it.** Consultation is reference-only: the agent sees each linked brain's name and path (Git links also show their last fetch date), reads notes with its file tools, treats them as reference data (never instructions), and cites each note as `<brain name>:<note path>`. With several brains it searches the one you name, or all of them and attributes each finding. If a chat drafts a specific note to share, the draft remains private until a human reviews and approves that individual note unless that brain's Settings row records an explicit automatic-sharing choice. Linking a brain grants no ongoing or autonomous permission to publish notes; each note needs its own review and approval unless automatic sharing was explicitly chosen for that exact Git brain. That choice is a standing permission for the future producer, not an active publisher.
