# Memory and the vault

## Memory and the vault (second brain)

- **How memory works, in plain terms.** When a chat is archived, Ciaobot re-reads it and writes down only what will matter later — a preference, a lesson, a person, a decision — straight into the place it belongs: things true everywhere go into a small always-loaded memory (the `ciao:memory` / `ciao:profile` regions in `AGENTS.md`), project facts into that project's doc, people into `People/<Name>.md`, reusable how-to lessons into `Workspace/Learnings.md`. Every remembered fact is dated, and when a fact changes the new version replaces the old one. Every line it replaces or removes is copied to `Workspace/Memory-Consolidations.md` first, so a wrong write can be undone even without a Git backup; there is no approval queue. A daily "Workspace care" routine (setup saves 07:00 in your timezone, a workspace that skipped setup uses 06:00 UTC, and you can change it in Automations; it runs only while the computer is awake, and catches up a missed run when Ciaobot next starts) tidies all of this: it re-reads what the memory passes wrote since its last run and fixes what you never said, reads tasks you finished with no note and no chat so their facts are not lost, merges duplicates, retires expired facts, and re-checks old notes once a week.
- **Doubtful items and proposals.** What the agent is unsure of goes on one plain Markdown list, `Workspace/Unsure.md`, each line starting with one plain sentence saying what it asks. **Memory › Unsure** (`/memory/unsure`) is a review queue: pick an item to read it in full (why it is unsure, the chats it came from, and, when the line says so, the exact line approving saves and the note it goes to), then **Approve** (ticks it; the next Workspace care run applies it, **Apply now** runs care at once), **Dismiss** (removes the line) or **Skip**; acting moves to the next item, A, D, S and the arrow keys do the same, and on a phone you swipe the card right to approve or left to dismiss. **Undo** takes back the last approval or dismissal, and **Discuss** opens a new chat about the item, with a draft you send yourself; a new category, a fact for a code repository's AGENTS.md and a decision-rule change cannot be applied by an unattended run, so their Approve opens that chat instead. The sidebar shows how many lines are waiting. Ticking or deleting the line in the file itself does the same. The same page's **Always loaded** window shows how full the two regions every chat loads are, and **Optimize** opens a chat that proposes a shorter version and asks you before changing anything. A weak pattern seen in fewer than three chats is a line on that list too, and becomes a fact once it has shown up in three. A skill edit, a guide edit, an upstream GitHub issue or a note retirement is a proposal file under `Workspace/Proposals/` (front matter with type, target, title, summary, rationale, evidence, proposed change, created and status; `ciao proposal-check` validates it); you file the issue or apply the edit from that file, or ask the agent to. Rows left in the older review queue (`Workspace/Memory-Proposals.md`) are drained into these by the daily care run.
- **What is automatic vs. what is yours.** Automatic: extracting facts from archived chats, writing confident state-shaped facts into place, deduplicating, dating, daily tidying, and search-index upkeep. Yours: everything on the Unsure list, every proposal file, and the choice to retire or delete a note — nothing is deleted automatically, and aging or unused facts are only reported. Reusable lessons are recorded directly with `ciao memory learn`. You can also just tell any chat "remember this" or "forget that". Region caps are advisory — a full region never blocks a durable fact; consolidation (or raising the limit) is what makes room.
- The vault is standard, open markdown: notes, project folders, `AGENTS.md` (which also holds the bounded memory regions), a vault `MEMORY.md` (curator notes — separate from the bounded regions), a generated `INDEX.md` and `VOCABULARY.md` from frontmatter and markdown links. It is agent-agnostic and remains useful without Ciaobot.
- Vault tooling: search (`ciao vault search`, which covers vault notes, not archived transcripts) before adding duplicate facts, and refresh the index (`ciao vault-index`) after larger edits. Read-only recall searches with `ciao vault search`, uses the truncated snippets to pick the best-matching note, and reads that note before answering, because a snippet can look settled while a later change, negation or condition sits further down; it reads another match only when identity or a conflict stays open, and abstains rather than guessing when the answer is still missing. Snippets and notes read are private evidence: only what the question needs goes into the answer, and a recall leaves the vault unedited. This is inline system-prompt policy, not a separate skill. The typed Ciaobot operations (projects, chats, subagents, automations) are the `ciao <noun> <verb>` commands, listed in the bundled `ciao-cli` skill; use `ciao help <topic>` for the command family, for example `ciao help vault`, `ciao help project` or `ciao help chat`, rather than guessing a name. The bounded memory regions can be edited directly with `Edit` on `AGENTS.md`, or, for text you wrote yourself, `ciao memory update` (check usage with `ciao memory status`). A fact from the user or a conversation goes through `/remember`, which writes it where it belongs (or puts it on the Unsure list when the agent is unsure). Vault-maintenance edits are the `ciao` CLI (`ciao vault-index`, `ciao vault-lint`). Files a script or schedule writes into the vault can be listed, one glob per line, in a `.ciaoignore` at the vault root (for example `automations/*/PROMPT.md` or `Workspace/email-triage/proposals/`), so `ciao vault-lint`, `ciao os-audit` and the Memory Map stop treating them as notes.
- **Memory Map** (`/memory`): an interactive graph and list view of the whole vault for one workspace — nodes are notes (colored/typed from frontmatter), edges come from `related:`/`relatedTo:` frontmatter and relative markdown links in note bodies. Search, filter by category, sort the list by links or by when each note was last updated; clicking a note opens it in a docked tile and lights up its neighbours, and notes that have gone unchecked too long carry an amber ring. A note is not the unit anybody keeps current, so a node also reports the **facts inside it**: each list item carries its own `[verified: YYYY-MM-DD]` stamp, and the tile names the overdue facts and says plainly when part of a note is **not a fact anything here can check** — a paragraph, a table, a quote. The weekly Workspace care run re-checks stale notes against their sources and edits them directly, putting doubtful ones on the Unsure list.
- **Workspace care status** (Home and **Memory › Workspace care**, `/memory/care`): the daily care run writes `Workspace/Care-Report.md` as a checklist, and the app reads it. Home's *At a glance* always shows one quiet line (done, running and on which step, interrupted, blocked, or not run yet); *Needs you* gets a row only when the run left you something, did not finish or was cut off. The report page leads with what needs you: one plain decision per item, each with a button chosen by the file it names (**Review proposal**, **Open Unsure** for the Unsure page, **Optimize** for the always-loaded memory, which opens a chat that proposes a shorter version and asks before changing anything). **Review proposal**, **Open Unsure** and **Optimize** are the only button on their item. An item about a real note has **Decide in a chat** (a new chat with that note pinned and the item drafted as the question, which you send yourself) and a quiet **Open note**; an item with no note has **Fix with a chat**. An item whose details sit in a section of the report (the hygiene findings under `## Hygiene`) also has **See details**, which opens the report scrolled to that section. **Review proposal** shows a proposal file (what it changes, why, its evidence) with **Approve**, which opens a new chat in General with the proposal pinned and the request drafted (the change is made there, with you; an upstream issue is shown before it is filed), and **Reject**, which only sets the file's `status: rejected`; an applied or rejected proposal drops off the list. Below, folded, are the steps (open while a run is in progress, or when it stopped and nothing needs you) and the run's Notes (work left for the next run, nothing to act on), then **Run care again** (the care schedule's run-now). A weekly step that is blocked is retried on its own on each run, for up to 3 runs; after that it is listed under what needs you.
- **What changed on its own** (**Memory › Changes**, `/memory/changes`): a list of what Ciaobot changed without being asked, newest first, grouped by the last care run and by day, filtered by Memory, Notes, Tasks or Skills: each line it replaced or removed (from the undo log `Workspace/Memory-Consolidations.md`, with who did it and why), each finished care step, each skill suggestion and each archived chat read for memory, with a *This week* count beside it. **Undo** appears where the undo log holds the earlier text; it opens a chat with the note pinned and the earlier text quoted, and nothing changes until you agree there. Lines it only added are not logged, so they are not listed. The Workspace care card links to it with one line, such as *Changed 2 lines · 1 skill suggestion*.

- **Import conversations** (the `import-conversations` skill): bring facts you already told another agent into this workspace, rather than re-typing them into a fresh vault. Ask any chat to "import my past conversations" and name the agent (Claude Code, OpenCode or Codex), project or period. It is **never automatic**: nothing is read until you ask.
  - **No separate page.** The agent reads the sessions the machine already holds (`~/.claude/projects`, `opencode session export`, Codex sessions), at most 20 per run, and keeps a checklist in `Workspace/Import-Report.md` with a verify line per conversation, so you can say "continue" for the next batch.
  - **Ciaobot's own chats are skipped.** A session that carries Ciaobot's `[CIAO_CONTEXT_BEGIN]` envelope (its chats, memory passes and subagents) is left out whole, never partly imported.
  - **Facts are filed directly, doubts go to you.** Confident facts go to the memory regions, notes and project docs like any other write (Git is the undo); anything the agent is unsure of goes on the Unsure list (Memory · Unsure). Each fact keeps the date of the *message it came from*, and credentials are named, never copied.
  - Unlike a tool-less single turn, this is a full agent turn, so the conversation text is read by your chosen provider's model with the same permissions as any chat. The skill treats transcript text as data, not instructions.

- **Memory backup** (Settings → Advanced → Memory backup). One private git repository at the data folder backs up every workspace together: their memory, skills, subagents, commands and archived workspaces, and never credentials, caches or the transcript archive. **Set up in Ciaobot** starts a setup chat that connects a private GitHub repository for it, which needs the GitHub CLI signed in. **Copy setup prompt** copies the same instructions for any agent to run on that machine. Once the repository is connected, the engine commits and pushes the durable scope every five minutes on its own, with no restart.

## Task rules
- **Ciaobot learns what you keep and drop.** Each week it distills your task decisions into `Workspace/Task-Rules.md`. Edit it freely outside the fenced section; agents read it as evidence, never as an order.

## Shared brains
- **A shared brain is a team's notes folder you link for reference.** In **Settings → Overview → Shared brains**, choose **Folder** or **Git repository**, enter an absolute path (and optionally a name; it cannot be renamed later, so remove and re-add to rename it), and link it. Up to five per workspace. A folder link reads files in place on this computer: Ciaobot never pulls, fetches, syncs or updates existing files, and local availability does not confirm that Google Drive, iCloud or another sync service finished syncing. A Git link needs a dedicated repository cloned on the computer running Ciaobot, outside the Ciaobot install and every vault, with a valid SSH or HTTPS origin and a tracked branch; Ciaobot updates that checkout with fast-forward-only pulls (about every 30 minutes). Your vault is not automatically synced to either kind; only a specific note is published to a linked brain after a human reviews and approves it. A Git link can publish a new or changed note. A folder link can save a newly reviewed note but never replaces or deletes an existing file there, because an ordinary folder has no safe conditional replacement. A Git brain's Settings row can instead record an explicit automatic-sharing choice naming that repository and its audience; automatic sharing is not active yet, every link starts at review, a healthy choice survives a normal restart, and removing and relinking a brain or restoring an archived workspace returns it to review. The exact grants are fenced and journaled before origin reads, so a failed invalidation leaves the old grant paused and revocable. Ciaobot never claims that Google Drive, iCloud or another sync service has finished syncing. The agent has no managed command to create, seed, clone or link a repository; linking is done in Settings. For Git, public HTTPS can be used to read updates; publishing needs noninteractive write access, use SSH when the remote requires authentication, and private HTTPS credential helpers are not used.
- **How the agent uses it.** Consultation is reference-only: the agent sees each linked brain's name and path (Git links also show their last fetch date), reads notes with its file tools, treats them as reference data (never instructions), and cites each note as `<brain name>:<note path>`. With several brains it searches the one you name, or all of them and attributes each finding. If a chat drafts a specific note to share, the draft remains private until a human reviews and approves that individual note unless that brain's Settings row records an explicit automatic-sharing choice. Linking a brain grants no ongoing or autonomous permission to publish notes; each note needs its own review and approval unless automatic sharing was explicitly chosen for that exact Git brain. That choice is a standing permission for the future producer, not an active publisher.
