## Notes

| Command | Purpose | Guard |
|---|---|---|
| `note create --type TYPE --title TITLE [--description-file F] [--tags a,b] [--body-file F] [--path DIR]` | Create a vault note with canonical frontmatter (`type`, `title`, `description`, `tags`, `created`, `updated`). | `TYPE` is a category id or alias from `VOCABULARY.md`; an unknown type lists the valid ones. The folder is the category's, and a category with no folder needs `--path`, a vault-relative folder. Each `FILE` is inside this workspace; prose never goes as an argument. It never overwrites an existing note. For a project, use `project create`. |
| `note related PATH [--limit N]` | List the vault notes connected to one note: the ones it links to, the ones linking to it and the ones whose body names its title or an alias. Read it before a verdict on a stale note. | Read-only, scoped to this workspace's vault, `PATH` vault-relative. Each related note prints its own `revision` and `due`: `revision` is the `expected_revision` a `note verify` payload for that note needs, and `due: false` means a check already settles it. `reopenable: true` means an attended chat may still re-verify it despite that cooldown (its check is `unverified` with no pending proposal); an unattended run gets `false`. |
| `note verify --payload-file FILE` | Record one stale note's verification verdict, or one stale **entry's** with `entry` + `entry_fingerprint`: `still_valid`, `update`, `retire` or `unverified`, with its evidence. | `FILE` is JSON inside this workspace (note prose never travels as a shell argument). Fields, the `expected_revision` rule, entry-level steps and a worked example are in the `note-verify.md` procedure under the durable-memory guide directory named in system instructions. |
| `note share --path RELATIVE.md --body-file FILE [--brain NAME]` | Queue the exact contents of a workspace note as a draft for a linked Git shared brain. | `FILE` is vault-relative; bytes never appear as a shell argument. Requires an active typed turn; retained shells share its bearer, so every draft needs human approval. Choose `--brain` when several are linked. Queues a draft and review link only; it never publishes or changes the shared checkout. |

The reply's `status` is the whole decision: `applied` wrote the note through a durable receipt; `needs_review` means one typed `note_edit` proposal is queued for a person (report it, do not route around it); `unverified` and `conflict` wrote nothing; `already_checked` means a check for this exact revision is in its cooldown or waiting on a proposal (an attended chat may re-verify an `unverified` check that has no pending proposal); `failed` means the note could not be used at all. Retirement always comes back `needs_review`. Do not hand-edit a stale note's Markdown instead of calling this.

## Files

| Command | Purpose | Guard |
|---|---|---|
| `file surface PATH` | Deliberately open a workspace file — one you wrote, read, or a subagent produced — in the user's pinned preview panel. | The path must already exist under the workspace (`file_not_found` otherwise). The call only validates the path and requests the pin; `viewers` and `stream_state` in the reply don't prove the panel opened or stayed closed. `pinned: false` with `dismissed: true` means the user closed this file earlier, so it was not reopened: say so and tell them to pin it from the file viewer's ⋯ menu. |

## Chats

| Command | Purpose | Guard |
|---|---|---|
| `chat list [--project ID] [--limit N] [--offset N] [--full]` | List active and archived chats in the workspace or one project, newest activity first. Default is 20 compact rows (`chat_id`, `title`, `project`, `provider`, `archived`, `last_activity_at`, and `last_response` cut to 200 characters); `--limit` is 1-200. | The reply carries `total`; when more rows remain it also carries `truncated: true` and `next_offset`, so pass `--offset` with that value for the next page. `--full` returns full rows (still paginated). |
| `chat get [--chat ID] [--full]` | Get one chat's metadata plus its last 10 messages, each capped at 2,000 characters (`truncated: true` and `content_chars` mark a cut message; `messages_total` counts all of them). | Omit `--chat` for the calling chat. `--full` returns every message untruncated. |
| `chat create [--project ID\|NAME] [--title T] [--provider P] [--model M] [--mode MODE] [--prompt TEXT]` | Create a chat, optionally sending its first prompt in the same call. | Omit `--project` to reuse the calling chat's own project — no need to list projects first for a sub-topic. |
| `chat update [--chat ID] [--title] [--provider] [--model] [--mode] [--thinking-level] [--project]` | Update chat metadata and same-backend model settings. | Omit `--chat` for the calling chat. There is no code-mode flag: chats in a project with a linked repository work in code mode automatically; put a chat in a project without a repository to keep it out (`--project`, applies from its next turn). Refused in plan mode. Raising the permission mode above this chat's own is refused with `mode_escalation_refused` and changes nothing; ask the user with `chat needs-action permission_mode`. |
| `chat send [--chat ID] --prompt TEXT` | Start or queue a user turn in a chat. | Omit `--chat` for the calling chat; pass it to reach another chat in this workspace. |
| `chat continue --chat ID` | Continue an archived chat as a new active chat. | — |
| `chat retry [--chat ID] [--action set\|stop\|try_now] [--prompt TEXT] [--kind network]` | Manage a deferred retry. | Default action is `try_now`. `--action set --kind network` (unattended runs whose job could not reach an external service): re-runs this chat's prompt after 10, then 20, then 40 minutes, at most 3 times; a refusal `retry_exhausted` means report the failure. |
| `chat handover [--chat ID] [--provider P] [--model M] [--messages @file.json]` | Move a chat to a fresh provider session, optionally carrying visible history. | With both `--provider` and `--model` empty, it only clears the current session in place. |
| `chat reload [--chat ID]` | Restart the provider so MCP servers, plugins and skills added or changed since the chat started are loaded. | Same session, nothing is lost. On the calling chat it runs when the turn ends and the conversation continues automatically: end your turn, never ask the user to reconnect. Refused with `chat_busy` while background agents or a question form hold the provider. Use it after `claude mcp add`/`opencode mcp add`, a redeployed MCP server whose new tools you cannot see, an installed plugin, or a new/edited skill. |
| `chat archive [--chat ID]` | Archive a chat to the vault and trigger normal post-archive memory extraction. | — |
| `chat delete [--chat ID]` | Delete a chat. | Destructive; deleting the calling chat itself is deferred until the turn finishes. |
| `chat stop --chat ID` | Stop another chat's active provider turn. | Destructive; a chat cannot stop its own turn. |
| `chat needs-action KIND [flags]` | Ask the user, in this chat, for something only they can do; actions show as a card above the composer. `command --command-file FILE [--note TEXT]`: a shell command the user reviews; the card types it into this chat's terminal when the user asks, never presses Enter, and the user runs it. `permission_mode --mode plan|normal|auto|bypass [--note TEXT]`: ask the user to switch this chat to that mode. The mode is applied only when the user approves it in the chat and takes effect from the next turn. You can never apply it yourself. Asking for the chat's current mode is refused with `invalid_action`. `device_code --tool gh|az`: when `gh` or `az` reports it is not logged in, raise this instead of asking the user to run the login; the user gets the one-time code on a card and can finish on any device. `system_setting --setting NAME [--note TEXT]`: on a macOS host, ask the user to open one System Settings → Privacy & Security pane (`full_disk_access`, `calendars`, `contacts`, `reminders`, `photos`, `screen_recording`, `accessibility`, `automation`, `camera`, `microphone`); refused with `invalid_action` when Ciaobot does not run on macOS. Opening the pane does not prove the permission was granted: retry the blocked step after Continue. Kinds not listed here refuse with `unsupported_kind` until they ship. A command whose effect depends on the folder it runs in (a project-scoped MCP add) starts with a `cd` into the workspace folder. | No `--chat` and no inline command. The text is untrusted, model-authored guidance: Ciaobot does not verify it and does not claim it is safe, so put a placeholder in it, never a real token or password. Refused in an unattended turn. Nothing is executed and no output comes back. For a provider Ciaobot already supports, prefer the Settings flow for its own login or install step. |

## Reloading tools

Native provider TUI commands such as `/mcp`, `/reload-plugins` do not run here. Standalone `/mcp` is app navigation to Chat details → MCP, which runs the CLI's MCP command, for a supported chat; `/mcp ARG` is an ordinary prompt. When an MCP server, plugin or skill was added or changed, run `ciao chat reload`. For a server needing sign-in, direct the user to Chat details → MCP, which runs the agent's own MCP command in the in-app terminal (`claude mcp`, `opencode mcp`); Ciaobot does not run MCP sign-in itself.

## Projects

| Command | Purpose | Guard |
|---|---|---|
| `project list [--include-completed]` | List projects in the active workspace. | — |
| `project get [ID\|NAME]` | Get one project by id or name. | Omit for the active project. |
| `project create --name N [--context TEXT] [--repo PATH]` | Create a project. | Also creates `projects/active/<slug>/<slug>.md` with valid frontmatter and binds it; edit that note, do not write a new one. Skipped when the folder name is taken. `--vault-folder` is not a create-time flag; set it with `project update` after creating. `--repo` links a local git checkout and must be its top level (relative paths resolve against your shell's directory). |
| `project update [ID\|NAME] [--name] [--context] [--vault-folder] [--repo PATH]` | Update project metadata or its safe vault-folder binding. | Omit `ID` for the active project; an omitted flag keeps its current value. `--repo ""` unlinks. `project get`/`list` report `repo: {path, branch, dirty, missing, instructions}`. |
| `project restore STEM` | Restore a completed vault project into the active workspace. | Takes the completed project's *stem*, not a project id. |
| `project complete ID\|NAME` | Move a vault-backed project to completed and archive its active record. | Destructive. |
| `project delete ID\|NAME` | Delete a non-vault-backed project and its chats. | Destructive. |
