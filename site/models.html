Bring the agent you already use

Claude Code, Codex and OpenCode already know how to reason, write code and call tools. Ciaobot drives the one you signed in to and adds the workspace, memory and files around it.

One layer on top, nothing in between

Ciaobot talks to each agent through the Agent Client Protocol, using a small adapter it installs on first use (Node 22 or newer). It never installs or replaces the agent itself: it runs the claude, codex or opencode already on your machine.

Why Ciaobot doesn't build its own agent

The agents are excellent and improve every week. Re-implementing them would mean always being behind. So Ciaobot leaves the thinking, the tool calls and the model access to them, and focuses on what they don't do: separate areas of your life, project context carried into every chat, memory you can review, routines that run on schedule, and documents beside the conversation.

Why not just use the agent directly? You can, and nothing stops you using both. Ciaobot is for when short tasks should share context, and what you learn should outlive the session.

Change your AI, not your second brain

Your notes, project context and remembered preferences stay in a folder you own, as ordinary Markdown, useful with another agent or a text editor even when Ciaobot is not running.

That is continuity of your workspace, not a promise that agent sessions are interchangeable. Each agent's tools, permissions and capabilities differ.

The three agents

Claude Code

Anthropic's agent, on your Claude subscription or API key. Sign in once with claude auth login.

Codex

OpenAI's agent CLI. Install @openai/codex and sign in with codex login. Settings can run both steps in its terminal.

OpenCode

Open source and bring-your-own-provider: OpenCode 2.3.2 or newer reaches OpenRouter, Ollama Cloud, local Ollama, LM Studio and many more. Connect them with opencode auth login.

Ciaobot never reads or stores a provider credential. Signing in is always the agent's own command.

Your connectors and MCP servers come along

Each agent owns its MCP servers, their sign-in and their on/off state, so whatever you have already set up keeps working in Ciaobot chats. That includes the connectors you enabled on claude.ai, such as Slack, Notion or Atlassian, which reach Claude Code sessions.

Settings → MCP opens each installed agent's own MCP command in the built-in terminal, so you add and sign in to servers the way that agent expects. Google Workspace connects the same way (how to add it). What else is built in →

Pick the agent per workspace, per chat, per job

  • Per workspace: choose the default agent in Settings, for example Claude Code for Work and a local model through OpenCode for Personal.
  • Per chat: change the model from the chat header.
  • Per job: automations and the memory pass each have their own model setting.
