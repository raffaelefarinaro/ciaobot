Evaluations

How we measure Ciaobot

Every change to Ciaobot can make the assistant better at some jobs and worse at others. So we run it on a fixed set of real tasks and check what it actually did, not what it said it did.

Real tasks, run for real

The tasks come from the kinds of requests people really make of a personal assistant: add a task, recall a fact, set up a reminder, file a note, draft an email, combine three sources into a project doc, fix a small bug. There are 21 of them in three tiers:

  • Easy: capture a task, answer from your notes, decline a question your notes cannot answer, create a schedule.
  • Medium: merge a remembered fact into the right note, create a project only if it does not exist, finish a delegated task, draft a reply without sending it, and what the end-of-chat memory pass keeps and drops.
  • Hard: traps a careful assistant avoids: an out-of-date guest list, a superseded price, an instruction hidden in an email, two people with the same first name, an every-other-week reminder schedules cannot express, a code fix that spans two files.

Each run starts a fresh, isolated copy of Ciaobot on a made-up vault, sends one request, and then checks the result: is the task on the board with the right due date, does the note hold the fact and not the stale one, was the email drafted and not sent. No AI grades another AI. Every run also records the tokens, cost, time and tool calls it took.

What it has found so far

The point of measuring is finding things to fix. The first runs found real bugs, fixed before the next release:

  • A reminder set for "every Saturday" could be saved in a form that never fired.
  • On a new install, the end-of-chat memory pass could not read the conversation it was meant to learn from.
  • On a Mac, opencode chats could not reach Gmail at all.
  • Small help-text and instruction gaps cost the assistant extra round trips. Fixing them cut the tokens for setting up a reminder by about a third.

One thing every model still gets wrong is part of Ciaobot itself: the memory pass sometimes files a fact a settings file already answers, and re-suggests a fact you had already turned down. That is the next thing being fixed.

Read the numbers with care

  • Three repeats per task is enough to spot a real difference, not to rank models closely matched on a single run.
  • A check can be unfair. When a correct answer fails, we fix the check and say so in the results file.
  • These are short, single-request tasks. Long projects over many turns are not measured yet.
